# Chromium GOST PowerShell Installer

## Цель

Сделать PowerShell-скрипт для Windows x64. Скрипт скачивает с GitHub последний опубликованный стабильный релиз Chromium-GOST, проверяет его и устанавливает или обновляет браузер. Он не должен зависеть от конкретного заказчика или внутренней инфраструктуры.

## Исходные данные

- Публичный источник релизов: GitHub `deemru/Chromium-Gost`.
- Для Windows x64 используется installer asset по шаблону `*windows-amd64-installer.exe`.
- Установка Chromium-GOST выполняется в системном контексте с ключами:
  `--system-level --install --do-not-launch-chrome`.
- Скрипт запускается локально на каждой Windows-машине, поэтому удаленный доступ и сетевое управление в него не включаются.
- Репозиторий публичный: секреты, внутренние имена, адреса, учетные данные и сведения об AVS не добавлять.

## Минимальная реализация

1. Проверить Windows PowerShell/PowerShell и права администратора.
2. Определить архитектуру и поддерживаемую ОС.
3. Получить нужный релиз Chromium-GOST через GitHub API.
4. Скачать ровно один подходящий installer во временный каталог.
5. Проверить SHA-256 скачанного файла; для production-повторяемости предусмотреть pin версии и хеша.
6. Проверить установленную версию и завершить работу, если нужная версия уже установлена.
7. Корректно закрыть процессы Chromium-GOST/Chrome перед обновлением.
8. Запустить installer с системными ключами и дождаться кода возврата.
9. Повторно проверить установленную версию и вывести понятный результат.
10. Удалить временный файл; ошибки должны возвращать ненулевой exit code.
11. Зарегистрировать локальную задачу Планировщика Windows для ежедневного запуска около 03:00 со случайной задержкой до 30 минут.

## Интерфейс

Основной файл: `Install-ChromiumGost.ps1`.

Параметры оставить минимальными:

- `-Version` — необязательно, установка конкретной версии;
- `-Sha256` — необязательно, обязательная проверка при pin-режиме;
- `-Force` — повторная установка/обновление;
- `-LogPath` — необязательно, путь к журналу.

Без параметров скрипт должен запускаться от имени администратора и брать последний опубликованный стабильный релиз.

## Надежность и безопасность

- Не использовать `Invoke-Expression`.
- Не запускать скачанный файл до проверки хеша, если задан ожидаемый хеш.
- Не хранить credentials и внутренние URL.
- Использовать TLS 1.2+ и явные таймауты.
- Не считать успешной установку только по коду `Start-Process`; нужна пост-проверка.
- Логировать версию, URL/имя asset, хеш, действия и коды возврата без секретов.

## Проверки перед публикацией

- Синтаксическая проверка PowerShell.
- Проверка режима `-WhatIf` или dry-run, если он не усложняет скрипт.
- Тест уже установленной актуальной версии.
- Тест обновления старой версии.
- Тест недоступного GitHub, неподходящей ОС, отсутствия прав и неверного SHA-256.
- README с примерами запуска и ограничениями.

## Что пока не делать

- Не добавлять удаленное управление, оркестратор, DVLS/Zabbix-интеграцию или серверную часть.
- Не добавлять CI/CD, модуль PowerShell и сложную конфигурационную систему до появления реальной необходимости.
- Не публиковать автоматически «latest» без возможности зафиксировать версию и хеш.
